# 旅行の日程調整・ルート決定アシスト（Chrome 拡張機能）

Google マップ上にサイドパネルを重ねて表示し、友達との旅行の **日程調整** と **ルート決定** を支援します。
Google カレンダーの予定を重ねて表示でき、確定した日程としおりをカレンダーへ登録できます。
サーバー・DB は不要です（データは `chrome.storage.sync` のみ）。Google Maps Platform の API は使用しません。

## ファイル構成

| ファイル | 役割 |
|---|---|
| `manifest.json` | Manifest V3 設定（**OAuth クライアント ID はここで差し替え**） |
| `background.js` | Service Worker。OAuth（`chrome.identity`）と Calendar API 呼び出し |
| `lib.js` | 共有コードの変換、距離計算（Haversine）、訪問順最適化、しおり生成 |
| `panel.js` / `panel.css` | Google マップ上のサイドパネル（Shadow DOM。マップの DOM には非依存） |

## セットアップ手順

### 1. 拡張機能の ID を確認する
1. Chrome で `chrome://extensions` を開き、右上の「デベロッパーモード」を ON にします。
2. 「パッケージ化されていない拡張機能を読み込む」でこのフォルダを選択します。
3. 表示された **拡張機能 ID**（32 文字）を控えます。(ebnbkpclibbcnakkgbniohfnjniihagf)
   - ※ 読み込みフォルダのパスが変わると ID も変わります。固定したい場合は、`manifest.json` に `"key"` を追加してください（[公式ドキュメント](https://developer.chrome.com/docs/extensions/reference/manifest/key)参照）。

### 2. Google Cloud Console の設定
1. [Google Cloud Console](https://console.cloud.google.com/) で **新しいプロジェクト** を作成します。
2. 「API とサービス」→「ライブラリ」から **Google Calendar API** を有効化します。
3. 「API とサービス」→「OAuth 同意画面」を設定します。
   - ユーザーの種類: 外部（個人利用なら「テスト」状態のままで可）
   - アプリ名・サポートメールなどを入力
   - **スコープ**に `https://www.googleapis.com/auth/calendar.events` を追加
   - 「テストユーザー」に、利用する自分と友達の Google アカウントを追加
4. 「認証情報」→「認証情報を作成」→「OAuth クライアント ID」を選択します。
   - アプリケーションの種類: **Chrome 拡張機能**
   - アイテム ID: 手順 1 で控えた **拡張機能 ID**
5. 発行された **クライアント ID** を `manifest.json` の `oauth2.client_id` に貼り付けます。
   ```json
   "oauth2": { "client_id": "123456-xxxx.apps.googleusercontent.com", ... }
   ```
6. `chrome://extensions` で拡張機能を **再読み込み** します。

### 3. 必要なスコープ
- `https://www.googleapis.com/auth/calendar.events`（予定の読み取りと作成）

> 公開（一般配布）する場合は、このスコープが「機密性の高いスコープ」に該当するため Google の OAuth 検証が必要です。個人・友人間利用ならテスト状態で運用できます（テストユーザーは最大 100 人、トークンは 7 日で失効することがあります）。

## 使い方

1. Google マップ（`google.com/maps` / `google.co.jp/maps`）を開き、右上の「旅」ボタンでパネルを開きます。
2. **日程タブ**
   - 幹事: 候補日を追加 → 「カレンダーの予定を読み込む」で既存予定を確認 → 「共有コードを発行」→ LINE 等で友達に送る。
   - 友達: ③に共有コードを貼り付け → 名前と出欠を入力 → 「返答コードを生成」→ 幹事に返す。
   - 幹事: ②に返答コードを順に貼り付けて集計（○の多い順に表示）→「確定」。
   - 幹事自身の出欠は、自分の共有コードを③に貼り付けて回答し、生成した返答コードを②に取り込むと集計に含められます。
3. **ルートタブ**: Google マップで場所を開いて「現在のページの地点を登録」→ 一覧の ☰ をドラッグして訪問順を決める（または「自動最適化」）→ 出発時刻・速度・迂回係数・滞在時間を設定。しおりは並べ替えのたびに自動で再計算されます。
4. **登録タブ**: 確定した日程としおりを Google カレンダーに登録します（結果が一覧表示されます）。
   - 日程全体の終日予定 1 件 ＋（任意）各地点の時刻付き予定を開始日に作成します。

## v1.1 の追加機能

- **登録した予定の削除（登録タブ）**: この拡張機能から登録した予定だけが一覧に出て、選択して削除できます（確認ダイアログあり）。
  - 登録成功時に eventId・タイトル・日時を `chrome.storage.sync`（`ev:<eventId>` のキー）に保存します。記録のない予定は、Service Worker 側でも削除を拒否します。
  - カレンダー側で既に削除済み（404/410）の場合は、その旨を表示して記録のみ整理します。認証エラーなどその他の失敗では、予定がカレンダーに残っているため記録は残し、再試行できるようにしています。
  - v1.0 で登録済みの予定は記録がないため、一覧には出ません（カレンダーから手動で削除してください）。
  - 必要スコープは `calendar.events` のまま（追加なし）です。
- **区間ごとの移動手段（ルートタブ）**: しおりの各区間で「車／電車」を切り替えられます（既定は車）。選択は区間ごとに保存され、移動時間の概算にはその手段の想定速度を使います。移動手段は「2 地点の組み合わせ」に紐づけて保持するため、並べ替えや最適化で区間の組み合わせが変わっても整合が取れます（向きが逆でも同じ区間として扱います）。
- **Google マップのルート案内リンク**: 各区間に「この区間のルートを見る」リンクを表示します（v1.2 から現在のタブ内で開きます）。`https://www.google.com/maps/dir/?api=1&origin=…&destination=…&travelmode=driving|transit` 形式で、`waypoints` は使わず、API キーも不要です。

## v1.2 の修正・追加

- **場所名の表示**: 登録時に URL の `/maps/place/<場所名>/` から場所名を取得（`+` は空白に、URL エンコードはデコード）し、一覧・しおり・ルートリンクの主表示にします。取得できない URL（`/maps/@緯度,経度,…z` など）でも登録でき、「名称未設定の地点」として登録されます。地点名は一覧からいつでも編集できます。
- **ルート案内を同じタブで開く**: 「この区間のルートを見る」は現在のタブ内で遷移します（Ctrl/⌘ クリックなどはブラウザ標準の動作）。遷移前に元の URL・表示タブ・スクロール位置を `chrome.storage.sync` に保存し、遷移後はパネルを自動で再表示して「← 元の画面に戻る」ボタンを出します。戻ると、元の画面でパネルとしおりの表示状態も復元されます（記録は 12 時間で無効）。
- **迂回係数**: 移動時間 = 直線距離 × 迂回係数 ÷ 想定速度。しおり上に概算である旨の注記を表示します。Routes API / Directions API は使いません。
- **ドラッグ&ドロップ並べ替え**: HTML Drag and Drop API のみで実装（ライブラリなし）。挿入位置は青線で表示され、並べ替え直後にしおりの時刻とルートリンクが再計算されます。
  - **訪問順は「一覧の並び」そのものです。** 先頭の地点が出発地点で、「自動最適化」は先頭を固定して残りの順を最適化し、手動の並びを上書きします。（v1.1 までの「出発地点」ラジオボタンと別保存の最適化結果は、この方式に統合しました。保存済みの最適化順は自動で移行されます）

## 仕様上の判断（変更しやすい箇所）

| 項目 | 内容 | 変更場所 |
|---|---|---|
| 想定速度 | 車 既定 40km/h・電車 既定 35km/h。ルートタブで変更可 | `panel.js` の `DEF.settings` / `lib.js` の `DEFAULT_SPEED` |
| 迂回係数 | 車・電車それぞれ既定 1.3（1.0 以上）。ルートタブで変更可 | `panel.js` の `DEF.settings` / `lib.js` の `DEFAULT_DETOUR` |
| 最適化アルゴリズム | 9 地点以下は総当たり（厳密解）、10 地点以上は最近傍法＋2-opt。出発地点は固定。地点は最大 20 件 | `lib.js` の `BRUTE_FORCE_MAX` |
| 候補日 | 開始日〜終了日（省略時は 1 日）。最大 60 件 | `lib.js` の `MAX_CANDS` |

## 注意事項・制限

- **緯度経度は URL からのみ取得**します。`!3d..!4d..`（場所の座標）を優先し、なければ `@緯度,経度`（地図の中心）を使います。場所を選ばず地図を動かしただけのページでは、中心座標が登録される場合があります。
- **`chrome.storage.sync` の容量制限**（1 項目 8KB／全体 100KB／最大 512 項目）があります。登録した予定の記録は 1 件ずつ別項目で保存しています。候補日・返答が極端に多いと保存に失敗し、エラーが表示されます。
- 返答は **名前で識別**します。同じ名前で再取り込みすると上書きされます。
- 共有コード／返答コードは Base64 化された JSON で、暗号化はされていません。個人のカレンダー予定の内容は含まれません。
- 取り込んだコードは内容を検証し、画面表示はすべてテキストとして扱います（不正なコードはエラー表示）。
- 移動時間は「直線距離 × 迂回係数 ÷ 想定速度」の概算です。実際の経路・交通機関・乗換は考慮しません。
