# 旅行の日程調整・ルート決定アシスト v2.0（Firebase リアルタイム共有版）

Google マップ上のサイドパネルで、友達との旅行の **日程調整・訪問地点の投票・ルート決定** をリアルタイムに共有しながら進める Chrome 拡張機能です。
確定した旅行は Google カレンダーに登録（メンバーへの招待メール付き）できます。

> **重要: この zip は「ソース一式」です。そのままでは Chrome に読み込めません。**
> Firebase SDK を拡張機能に同梱するため、`npm run build` でビルドして `dist/` を作り、その `dist` フォルダを読み込みます（手順 7〜8）。

## v1.2 からの変更点

| 項目 | v1.2 | v2.0 |
|---|---|---|
| 共有方法 | 共有コード／返答コードを LINE 等でやり取り | **Firebase Realtime Database でリアルタイム共有** |
| 共有するもの | （コードでやり取り） | メンバー・候補日・出欠・候補地点・投票・採用した地点 |
| 旅行 | 1 件のみ | **旅行ごとに分離**（一覧・新規作成・削除・切り替え） |
| 幹事／メンバー | 区別なし | 招待制。**招待されたメンバーだけ**がデータを読める |
| 訪問地点・しおり・移動手段 | ローカル | 幹事のローカルのみ（旅行ごと） |
| カレンダー登録 | 自分の予定のみ | **メンバーを招待**（招待メール）、場所・説明欄にしおり |
| ルート案内 | 区間ごとのリンク | 区間リンク + **全体ルートのリンク**（経由地の上限対応） |
| 配布 | zip を読み込むだけ | **ビルドが必要** |

**v1.2 で保存したデータ（訪問地点・登録済み予定の記録など）は引き継がれません。** v1.2 で登録した予定は、Google カレンダーから手動で削除してください。

## 全体像: 誰が何をするか

- **幹事（1 人）**: Firebase プロジェクトと Google Cloud の設定、ビルド、友達への `dist` の配布を行います。
- **友達**: 幹事から受け取った `dist` フォルダを Chrome に読み込み、Google でサインインするだけです（npm などは不要）。幹事に招待されると、自動で旅行が一覧に表示されます。
- **Firebase プロジェクトは、友達グループで 1 つ**です。友達が別々に作ると同じデータを共有できません。
- Google の認証は **拡張機能 ID に紐づく**ため、全員が同じ ID である必要があります。`static/manifest.json` に `key` を固定してあり、拡張機能 ID は常に次の値になります。

```
kdhojbgokcianbdogkbnmamllolhaohm
```

## 準備するもの

Node.js 18 以上（20 LTS 推奨）、Chrome 116 以上、Google アカウント（幹事・友達全員）。Firebase は無料の Spark プランで足ります。

## セットアップ（幹事）

### 1. Firebase プロジェクトを作る
[Firebase コンソール](https://console.firebase.google.com/) →「プロジェクトを追加」。Google アナリティクスは不要です。

### 2. Realtime Database を作る
左メニュー「構築」→「Realtime Database」→「データベースを作成」。ロケーションは任意、セキュリティルールは **「ロックモード」** を選びます。作成後に表示される URL（`https://…firebaseio.com` または `https://…firebasedatabase.app`）を控えます。(https://michiru2-b438b-default-rtdb.firebaseio.com/)

### 3. Google ログインを有効にする
「構築」→「Authentication」→「始める」→「Sign-in method」→ **Google** を有効にし、サポートメールを選んで保存します。

### 4. Web アプリを登録して設定値を入れる
「プロジェクトの設定」→「マイアプリ」→ Web アプリ（`</>`）を追加。表示される `firebaseConfig` の値を、このフォルダの **`firebase-config.json`** に貼り付けます。

```json
{
  "apiKey": "…", "authDomain": "…", "databaseURL": "手順 2 の URL", "projectId": "…", "appId": "…"
}
```

（`apiKey` は公開されても問題のない識別子です。データは次の手順のセキュリティルールで守られます。）

### 5. セキュリティルールを公開する
Realtime Database →「ルール」タブに、**`database.rules.json` の内容をそのまま貼り付けて「公開」** します。このルールで次を強制します（画面側の制限に加えて、サーバー側でも守られます）。

- 旅行のデータを読めるのは、**その旅行に招待されたメンバーのみ**（招待リストの中に、自分のメールアドレスがある人）。
- 招待・候補日の追加と削除・候補地点の「採用」・旅行の削除は **幹事のみ**。
- 出欠と投票は **自分の分だけ** 書き込める。
- 候補地点の追加は全員可。削除は追加した本人と幹事のみ。
- Google アカウントのメールが **確認済み**（`email_verified`）であることを要求します。

### 6. Google Cloud の設定（Firebase と同じプロジェクト）
Firebase プロジェクトは、そのまま Google Cloud のプロジェクトでもあります。[Google Cloud コンソール](https://console.cloud.google.com/)で **同じプロジェクト** を選び、次を行います。

1. 「API とサービス」→「ライブラリ」→ **Google Calendar API** を有効化。
2. 「OAuth 同意画面」を設定（ユーザーの種類は「外部」、公開ステータスは「テスト」のままで可）。
   - **スコープ**を追加: `openid`、`…/auth/userinfo.email`、`…/auth/userinfo.profile`、`https://www.googleapis.com/auth/calendar.events`
   - **テストユーザー**に、**メンバー全員の Google アカウント** のメールアドレスを追加（追加していない人は「アクセスをブロック」されます）。
3. 「認証情報」→「OAuth クライアント ID を作成」→ 種類は **「Chrome 拡張機能」**、アイテム ID に上記の拡張機能 ID（`kdhojbgokcianbdogkbnmamllolhaohm`）を入力。
4. 発行されたクライアント ID を **`static/manifest.json` の `oauth2.client_id`** に貼り付けます。(958916747277-oa3sftt94ri8ds5044318n5ivqb3a4h4.apps.googleusercontent.com)

### 7. ビルドする
```
npm install
npm run build
npm run verify
```
`dist/` フォルダができます。`npm run verify` は、`dist/` にリモートコード（外部から読み込むスクリプト）への参照が無いことを検査します（Manifest V3 の要件）。

### 8. Chrome に読み込む
`chrome://extensions` →「デベロッパーモード」ON →「パッケージ化されていない拡張機能を読み込む」→ **`dist` フォルダ** を選択。表示される ID が上記の ID と一致することを確認します。

## 友達への配布
`dist` フォルダを zip にして渡します（Firebase の設定とクライアント ID が入った状態です）。友達は解凍して、手順 8 の方法で読み込み、パネルの「旅行」タブから Google でサインインします。**友達のアカウントがテストユーザーに登録済み**であることを確認してください。

## 使い方

1. Google マップを開き、右上の「旅」ボタンでパネルを開く →「旅行」タブで **Google でサインイン**。
2. **旅行**: 新規作成すると自分が幹事になります。メンバーをメールアドレスで招待すると、相手の一覧に自動で表示されます。メンバーの状態は「参加済み」（招待後、その旅行を初めて開いた）／「招待中（未参加）」で表示されます。
3. **日程**: 幹事が候補日を追加。全員が出欠（○△×）を入力すると、**全員の画面にすぐ反映**され、参加可能人数の多い順に並びます。「自分のカレンダーの予定を重ねて表示」で、予定のある日に警告が出ます。幹事は「この日で確定」を押します。
4. **投票**: Google マップで場所を開いて「候補に追加」。全員が「行きたい」に投票でき、得票数と投票者が表示されます。幹事が「採用」にチェックし、「訪問地点リストに取り込む」でルートへ引き継ぎます（採用の状態は全員に表示）。
5. **ルート**（幹事）: ☰ のドラッグで訪問順を並べ替え（または自動最適化）、区間ごとに車／電車を選択。しおりの時刻と、区間ごと・全体のルート案内リンクがその場で更新されます。
6. **登録**（幹事）: 確定した日程を Google カレンダーに登録。**メンバーが招待され、招待メールが送られます**。説明欄にしおり全体（時刻・滞在・移動手段・ルートリンク）、場所に最初の訪問地点が入ります。登録した予定は一覧から削除できます（ゲストにはキャンセル通知が送られます）。

## 権限（誰が何をできるか）

| 操作 | 幹事 | メンバー |
|---|---|---|
| 旅行の作成 | ○ | ○（作った人が幹事） |
| 旅行の削除・メンバー招待／解除 | ○ | × |
| 候補日の追加・削除、日程の確定 | ○ | × |
| 出欠の入力 | ○（自分の分） | ○（自分の分） |
| 候補地点の追加／投票 | ○ | ○ |
| 候補地点の削除 | ○（全件） | 自分が追加したもののみ |
| 候補地点の採用 | ○ | × |
| 訪問地点・ルート・カレンダー登録 | ○ | ×（画面に案内を表示） |

## 仕様上の判断

- **Firebase の接続は offscreen ドキュメントで保持**します。Service Worker はアイドルで停止し、Google マップのページ内ではページ側の制約を受けるためです。Service Worker は OAuth・Calendar API・状態の中継だけを担当し、状態はすべて `chrome.storage` に保存します（モジュール変数に持ちません）。offscreen は `chrome.runtime` しか使えないため、Firebase の更新は Service Worker 経由で `chrome.storage.local` に書かれ、パネルが変更を監視して再描画します。
- **旅行の一覧（招待された旅行）**: Realtime Database は旅行をまたいだ検索ができないため、メールアドレスをキーにした索引 `userTrips/<メール>/<旅行ID>` を、幹事が招待時に書き込みます。キーのメールアドレスは小文字化し、`.` を `,` に置き換えます（ルール側も同じ変換）。
- **「採用」と訪問地点リスト**: Firebase に置くのは「採用済み」の印だけです。訪問地点リスト・しおり・区間ごとの移動手段・確定日程・登録済みカレンダー予定は、幹事の `chrome.storage.local`（旅行ごと）にだけ保存されます。幹事が別の PC を使うと、それらは引き継がれません。
- **参加済み**: 招待されたメンバーが、その旅行を初めて開いた時点で記録します（一覧に表示されただけでは「未参加」のままです）。
- **全体ルート**: 経由地の上限（モバイル 3 件 / それ以外 9 件）と URL の 2,048 文字制限に合わせて、先頭から収まる地点までを案内し、超えた場合は警告を表示します。カレンダー予定のリンクは、スマートフォンで開く前提でモバイルの上限（3 件）に合わせています。
- 移動手段・想定速度・迂回係数・訪問順の最適化は v1.2 と同じです（先頭の地点が出発地点）。

## 制限・注意

- **メールアドレスの表記**: 招待するメールアドレスは、相手が Google でサインインに使うものと一致している必要があります。Gmail のドット違い（`a.b@gmail.com` と `ab@gmail.com`）は別のアドレスとして扱われ、一致しません。
- **招待メール**: Google カレンダーを使っていないメールアドレスの方には、招待メールが唯一の伝達手段で、予定は自動では追加されません。参加者の設定によっては、メール内で出欠に回答するまでカレンダーに追加されない場合があります（登録画面にも表示されます）。
- **テストユーザー**: OAuth 同意画面が「テスト」の間は、登録したテストユーザーのみ利用でき（最大 100 人）、トークンが 7 日で失効することがあります。その場合は再度サインインしてください。一般公開する場合は Google のアプリ審査が必要です。
- **Firebase の無料枠（Spark）**: 同時接続 100、ダウンロード 10GB/月、保存 1GB。友達グループの利用には十分です。
- 候補日は最大 60 件、候補地点は最大 50 件、訪問地点は最大 20 件です。候補地点の名前は、追加後に変更できません（削除して追加し直してください）。
- カレンダーの「場所」には、最初の訪問地点の名前を入れます（名前が未設定のときは座標）。名前によっては Google カレンダー側で住所に解決されない場合があります。

## セキュリティルールの確認

Firebase コンソールの Realtime Database →「ルール」→ **「ルールプレイグラウンド」** で、次のような確認ができます（本番データに影響しません）。

- 招待されていないアカウントで `/trips/<旅行ID>` を読む → 拒否される
- メンバーが `/trips/<旅行ID>/dates/…` に書く → 拒否される（幹事のみ）
- メンバーが他人の `/trips/<旅行ID>/answers/<他人のキー>/…` に書く → 拒否される

ローカルで確認する場合は Firebase Emulator Suite（`firebase emulators:start`）も使えます。

## トラブルシュート

- **「Firebase の設定が未設定です」**: `firebase-config.json` を編集して、`npm run build` をやり直してください。
- **「manifest.json の oauth2.client_id が未設定です」**: `static/manifest.json` の `client_id` を設定してビルドし直してください（`dist/manifest.json` を直接編集しても動きますが、次のビルドで上書きされます）。
- **サインインに失敗する**: ①Authentication で Google が有効か ②OAuth クライアントが Firebase と同じプロジェクトにあるか ③アイテム ID が拡張機能 ID と一致しているか ④テストユーザーに登録済みか、を確認してください。
- **「権限がありません」**: 招待されていない、または幹事のみの操作です。セキュリティルールが公開されているかも確認してください。
- **リモートコードが検出された場合（`npm run verify` が NG）**: `src/offscreen.js` が `firebase/auth/web-extension`（拡張機能用のエントリ）を読み込んでいること、`firebase` が `package.json` の指定（11.10 以上）でインストールされていること（`npm install` をやり直す）を確認してください。それでも出る場合は、NG の出力内容を添えてご連絡ください。
