## 2. システム概要と対象範囲

MICHIRUは Google マップ上に表示される Chrome 拡張機能である。Google アカウントで認証し、Firebase Realtime Database を介して旅行情報、メンバー、日程回答、スポット投票を共有する。旅行のルート・しおりを作成し、Google マップや Google カレンダーと連携する。Gemini、Google Maps Geocoding、Places API を利用する提案・レビュー機能も対象とする。

| 機能領域 | 主な確認内容 |
|---|---|
| 拡張機能・パネル | 対象 Google マップでの表示、起動、開閉、位置・サイズ・透明度の保存 |
| 認証・権限 | Google サインイン、未認証時の案内、権限不足・通信失敗時の表示 |
| 旅行・メンバー | 旅行作成・選択・削除、メンバー招待・解除、幹事／参加者の権限 |
| 日程調整 | 候補日管理、○／△／×回答、集計・確定 |
| 行きたい場所 | 候補登録・編集・削除、投票、順位表示、レビュー要約・AI提案 |
| ルート・しおり | 地点追加・並べ替え・削除、移動手段・滞在時間・時刻、ルート表示 |
| カレンダー | 予定登録、参加者招待、登録済み予定一覧・削除 |
| データ・復旧 | Firebase リアルタイム同期、再読込・再起動後の状態復元、エラー時の整合性 |

## 3. テスト環境・前提

- Google Chrome 116 以降。Google マップの `www.google.com/maps`、`www.google.co.jp/maps` または `maps.google.com` を使用する。
- テスト用 Google アカウント（幹事用・招待参加者用）と、テスト用 Firebase 環境を用意する。
- カレンダー登録・メール送信を確認する場合は、Google Calendar／Gmail API の同意と権限が有効なアカウントを使用する。
- AI提案・場所レビューは必要な API キーと利用可能なネットワークを用意する。外部サービスが使えない場合はエラー表示・再試行を確認し、機能の正常結果と区別して記録する。
- テストデータには実在する個人情報を使わない。招待先はテスト用アドレスとする。
- 実施前に拡張機能を読み込み、拡張機能のバージョン、Chrome バージョン、OS、使用アカウント、環境（開発／検証）を記録する。

## 4. 判定・記録方法

各ケースを手順どおり実施し、期待結果を満たせば「合格」、満たさなければ「不合格」、環境未準備などで確認できない場合は「未実施」とする。実施結果欄に実際の表示・値を記録し、不合格時は不具合番号、再現手順、画面キャプチャを添付する。既存の Node.js テストが確認している内容は「単体テストで確認」と記し、画面・外部サービスを含む確認は別途実施する。

## 6. 既存の自動テストとの対応

リポジトリ内の `test/` を確認した時点で、Node.js テストは主に次を対象としている。自動テストが通っても Chrome 上の表示や Google／Firebase 外部サービスとの実動作を保証するものではないため、上記の連携・画面テストも実施する。

- メール形式とキー変換、日程・スポット投票の順位付け
- ルート URL の生成、経由地上限、移動時間・しおり HTML の生成、Google マップ URL の解析
- Firebase offscreen 処理の認証中継、旅行作成・招待・削除、回答・場所・投票等の書き込み処理
- パネルの起動に関するスモーク確認
